#### WR-586. Temporary Boolean operand transforms discard failures
- **Severity:** Wrong result
- **Area:** Booleans / coordinate transforms
- **Location:** `source/SMLib/src/SmMerge.cpp:2338-2386`, `SmTemporaryBrepTransform` constructor and destructor, pinned v1.0.1 `3fd5b95`.
- **What happens:** the constructor ignores both operands' `Transform` statuses and the destructor ignores each surviving operand's inverse-transform status. A failed forward translation can leave operands in different coordinate systems while the Boolean continues. A failed inverse can leave the result in translated coordinates while the operation reports success.
- **Trigger:** a failed operand transform when the combined bounding-box center's squared distance from the origin exceeds `1e6`.
- **How found:** issue #483's status audit, followed by source inspection and a failing Rust regression: an injected inverse-transform error returned `Ok(())` from `TemporaryBrepTransform::restore`.
- **Confirmed:** no C++ failure-path execution; the native implementation visibly ignores the returned statuses. Rust callback failures reproduce the discarded error deterministically. The new far wire/face fixtures exercise successful native shifts and restoration, not native transform failures.
- **Rust port (PR #1775, issue #1781):** opt-in `Kernel::fixes.boolean_temporary_transform_statuses`, default `false` for reference parity. The first failed forward translation stops the operation. If the second fails, the primary's successful translation is undone; a failed undo is returned instead. Cleanup attempts every surviving operand and returns the first inverse-transform error, taking precedence over the Boolean's result. Partial mutations inside a failed transform are not transactional. Bounding-box status handling and the other status-audit paths of #483 are outside this fix.
- **Tests:** `boolean::merge::p1::tests` covers forward failures on either operand, undo failure, first-error precedence, deleted operands, cleanup after Boolean failures, default ignored statuses, and real box geometry round trips. `fixtures/boolean.merge_p1/temporary-transform.json` adds positive/negative far wires and a far planar face to the native comparison without changing tolerances.
